# ⏱️ FalconAI — Учёт рабочего времени сотрудников

Простое и удобное веб-приложение для учёта рабочего времени команды: добавление сотрудников, запуск живого таймера по задачам, просмотр истории и сводных отчётов за период.

---

## ⚡ Быстрый старт (в 2 команды)

Требуется **Node.js** версии 20+ и npm.

```bash
# 1. Установить зависимости сразу для всего проекта
npm run install:all

# 2. Запустить сервер и клиент одной командой
npm run dev
```

- **Фронтенд**: http://localhost:3000  
- **Бэкенд**: http://localhost:5000  

При первом старте база SQLite создаётся автоматически и наполняется тестовыми сотрудниками и демонстрационными записями.

---

## 🛠️ Стек
- **Frontend**: React 18, TypeScript, Ant Design, Tailwind CSS v4, React Query (TanStack).
- **Backend**: Node.js 24, Express, TypeScript, встроенный `node:sqlite` (SQLite без лишних зависимостей).
- **Хранение**: Локальная база SQLite (`.sqlite`) — данные сохраняются при перезапуске приложения.

## 🐛 Ошибки, которые нашли и исправили

1. **Проблема сборки `better-sqlite3` на Windows**:  
   *Что было*: В Node 24 пакет `better-sqlite3` требовал компилятор C++ Visual Studio и падал при установке.  
   *Как решили*: Перешли на встроенный в Node.js 24 модуль `node:sqlite`. Он не требует компиляции, ставится мгновенно и работает нативно.
2. **Сброс секундомера при обновлении страницы**:  
   *Что было*: Если считать секунды просто через `+1` в стейте, то при F5 всё обнулялось.  
   *Как решили*: В базу пишем точное время старта `startTime`. В браузере секундомер каждую секунду вычисляет `сейчас - startTime`. Теперь страницу можно закрывать, обновлять или перезапускать сервер — время идёт точно.
3. **Постфиксный модификатор Tailwind `!`**:  
   *Что было*: По манифесту класс пишется как `flex!`, `bg-sky-600!`. Старый Tailwind v3 такой синтаксис игнорировал (ждал `!flex`).  
   *Как решили*: Подключили Tailwind CSS v4 через нативный плагин `@tailwindcss/vite` — в v4 постфиксный `!` поддерживается из коробки.
4. **NaN и null в пустом отчёте**:  
   *Что было*: Если за выбранные даты не было записей, SQL-запрос `SUM()` отдавал `null`, и на фронте рисовалось `NaN ч NaN мин`.  
   *Как решили*: Добавили `COALESCE(SUM(...), 0)` в SQL и компонент `EmptyState` на фронте.

## 🧪 Проверка основных сценариев

1. **Добавление сотрудника**:
   Вкладка «Сотрудники» ➡️ кнопка «Добавить сотрудника» ➡️ заполняем форму ➡️ сотрудник сразу появляется в карточках и доступен в таймере.
2. **Запуск и остановка таймера**:
   Вкладка «Трекинг» ➡️ выбираем сотрудника, пишем задачу ➡️ жмём «Запустить таймер» ➡️ появляется карточка с тикающим секундомером ➡️ жмём «Остановить» ➡️ сессия сохраняется в истории.
3. **Повторный запуск таймера (защита)**:
   Запустите таймер для сотрудника А. Попробуйте снова выбрать его в форме запуска — он будет помечен серым (disabled), появится жёлтый `Alert`. Если отправить запрос напрямую через API — сервер вернёт `400 Bad Request` с пояснением.
4. **Пустой отчёт**:
   Вкладка «Отчёты» ➡️ выберите в календаре дату в будущем (например, следующий год) ➡️ появится аккуратный блок: *«Пустой отчёт: за выбранный период данных нет»*.
5. **Сохранение после перезапуска**:
   Запустите таймер или добавьте сотрудника. Остановите сервер в консоли (`Ctrl + C`) и запустите снова (`npm run dev`). Обновите страницу — таймер продолжает тикать, все данные на месте.

## 📁 Структура кода коротко

- `server/src/modules/employees/` — логика сотрудников (добавление, список, удаление).
- `server/src/modules/time-entries/` — логика таймеров (старт, стоп, журнал).
- `server/src/modules/reports/` — SQL-агрегация общего времени по сотрудникам.
- `client/src/widgets/` — готовые блоки интерфейса: форма таймера (`timer-section`), таблица записей (`time-entries-table`), отчёты (`reports-summary`), управление сотрудниками (`employee-management`).
- `client/src/features/` — мелкие действия: карточка тикающего таймера (`timer-active-card`), фильтр дат (`period-filter`), модалки добавления.
