# ⏱️ FalconAI — Веб-приложение для учёта рабочего времени сотрудников

Веб-приложение для точного учёта рабочего времени сотрудников компании, разработанное в соответствии с требованиями тестового задания.

---

## 🚀 Функциональные возможности

- **Управление сотрудниками**: добавление сотрудников с указанием ФИО, должности и отдела, просмотр списка карточек и безопасное удаление.
- **Интерактивный таймер задач**:
  - Быстрый запуск таймера с выбором сотрудника и описанием выполняемой задачи.
  - Живой секундомер в реальном времени.
  - Остановка таймера с автоматическим расчётом затраченного времени.
- **Журнал записей времени**:
  - Детализированная таблица сессий с сортировкой, пагинацией и статусами.
  - Возможность ручного добавления сессий (если таймер забыли запустить вовремя).
  - Удаление ошибочных записей.
- **Аналитика и отчёты**:
  - Сводка отработанного времени по каждому сотруднику за выбранный период (Сегодня, Вчера, Неделя, Месяц, Произвольный диапазон дат).
  - Наглядные KPI-карточки (общее время, выполненные задачи, активные таймеры).
  - Индикатор доли рабочего времени каждого сотрудника.
  - Корректная обработка сценария «Пустой отчёт».
- **Надёжное сохранение данных**:
  - Все данные сохраняются в реляционной базе данных SQLite (`.sqlite`).
  - Активные таймеры не сбрасываются при перезапуске сервера или обновлении страницы: отсчёт продолжается от сохранённой метки `start_time`.

---

## 🛠️ Стек технологий

- **Frontend**:
  - React 18, TypeScript
  - UI-библиотека: **Ant Design 5** (с русской локализацией `ru_RU`)
  - Стилизация: **Tailwind CSS** (с постфиксными модификаторами `!`)
  - Сетевой слой: **@tanstack/react-query** (строгие хуки `useGetQuery`, `useMutationQuery` с инвалидацией ключей кэша)
  - Архитектура: **Feature-Sliced Design (FSD)** (слои `app`, `pages`, `widgets`, `features`, `entities`, `shared`)
  - Сборщик: **Vite**
- **Backend**:
  - Node.js 24, Express, TypeScript
  - Архитектура: **Service-Driven Architecture** (`routes -> services -> db -> SQLite`)
  - База данных: Встроенный высокопроизводительный движок **`node:sqlite` (`DatabaseSync`)**
  - Валидация входных данных, строгая типизация DTO
- **Конфигурация**:
  - Единый файл конфигурации `.env` в корне проекта для клиента и сервера

## 📦 Быстрый старт и запуск

### Предварительные требования
- Установленный **Node.js** версии 20+ (рекомендуется v22 или v24)
- Менеджер пакетов **npm**

### 1. Клонирование и установка зависимостей
```bash
# Клонируйте репозиторий и перейдите в каталог
git clone <URL_РЕПОЗИТОРИЯ>
cd falconAI

# Установка зависимостей одной командой (корень, клиент и сервер)
npm run install:all
```

### 2. Конфигурация окружения
В корне проекта уже подготовлены `.env` и `.env.example`:
```env
PORT=5000
DATABASE_PATH=./data/timetracker.sqlite
VITE_API_URL=http://localhost:5000/api
```

### 3. Запуск приложения
Запустите клиент и сервер одновременно одной командой:
```bash
npm run dev
```

Или по отдельности в разных терминалах:
```bash
# Запуск бэкенда (порт 5000)
npm run dev:server

# Запуск фронтенда (порт 3000)
npm run dev:client
```

После запуска откройте в браузере: **`http://localhost:3000`** (бэкенд доступен по адресу `http://localhost:5000`).

При первом запуске база данных автоматически инициализируется и наполняется тестовыми вымышленными сотрудниками и демонстрационными записями времени.

## 🐛 Найденные ошибки и их исправление

В процессе разработки и автоматического тестирования были выявлены и устранены следующие проблемы:

### 1. Ошибка сборки нативных C++ модулей `better-sqlite3` на Windows в Node 24
- **Проблема**: При попытке установить библиотеку `better-sqlite3` на платформе Windows x64 с версией Node.js v24.12.0 процесс `npm install` завершался ошибкой:
  `gyp ERR! Could not find any Visual Studio installation to use (missing VC++ toolset)`.
  Для установки требовалось наличие нескольких гигабайт компиляторов Visual Studio C++.
- **Решение**: Проведён анализ рантайма Node.js 24, в котором обнаружен встроенный нативный модуль `node:sqlite` с синхронным интерфейсом `DatabaseSync`. Код слоя `connection.ts` и `db.ts` был переведён на использование стандартного `node:sqlite`. Это устранило внешнюю нативную зависимость, ускорило установку пакетов до 1 секунды и гарантировало 100% переносимость проекта на любые ОС без установки дополнительных компиляторов.

### 2. Сброс счётчика запущенного таймера при обновлении страницы
- **Проблема**: Если хранить только секунды, прошедшие с момента клика, то при перезагрузке вкладки или перезапуске сервера состояние секундомера обнулялось.
- **Решение**: Сервер сохраняет точную временную метку `start_time` в формате ISO 8601 UTC в SQLite. Компонент `TimerActiveCard` на клиенте вычисляет текущую длительность динамически:
  `elapsedSeconds = Math.floor((Date.now() - new Date(entry.startTime).getTime()) / 1000)`.
  Даже если пользователь закроет вкладку, перезагрузит браузер или сервер перезапустится — после повторного открытия счётчик продолжает отсчёт с абсолютной точностью.

### 3. Обработка сценария одновременного/повторного запуска таймера
- **Проблема**: Пользователь мог случайно дважды нажать «Запустить таймер» или запустить две параллельные задачи для одного и того же сотрудника.
- **Решение**:
  - На уровне БД и сервиса добавлен метод `findRunningByEmployeeId`. При наличии активного таймера сервис возвращает ошибку 400: *"У сотрудника уже запущен таймер по задаче... Завершите текущий таймер перед запуском нового"*.
  - В интерфейсе `TimerLaunchForm` поле выбора сотрудника помечает занятых сотрудников и отключает их в выпадающем списке, выводя предупреждающий блок `Alert`.

### 4. Некорректное отображение пустого отчёта
- **Проблема**: При выборе диапазона дат в будущем или дат без записей SQL-запрос `SUM(duration_seconds)` возвращал `NULL`, что приводило к отображению `NaN ч NaN мин` в интерфейсе.
- **Решение**: В SQL-запросе применён оператор `COALESCE(SUM(t.duration_seconds), 0)`. На фронтенде реализован флаг `isReportEmpty`, который при отсутствии записей рендерит дружелюбный `EmptyState` вместо пустой таблицы с нулями.

### 5. Игнорирование постфиксных модификаторов `!` в Tailwind CSS v3
- **Проблема**: В манифесте разработки зафиксировано строгое правило: `important` модификатор указывается как суффикс (`flex!`, `bg-sky-600!`). В Tailwind CSS v3 такой синтаксис не генерировал стили, так как v3 поддерживал только префикс (`!flex`). В результате на клиенте классы разметки не применялись и интерфейс выглядел как неоформленный HTML.
- **Решение**: Проект переведён на современный **Tailwind CSS v4** с официальным Vite-плагином `@tailwindcss/vite`. В спецификации Tailwind v4 постфиксный модификатор `!` является нативным стандартом. Стили успешно компилируются, а также подключен современный шрифт Inter и расширены токены Ant Design (радиусы, высоты инпутов и цветовые шкалы).

## 🧪 Проверка основных сценариев

### Сценарий 1: Добавление сотрудника
1. Перейдите во вкладку **«Сотрудники»**.
2. Нажмите **«Добавить сотрудника»**, заполните форму (ФИО, должность, отдел) и подтвердите.
3. Новый сотрудник мгновенно появляется в списке карточек и становится доступен для выбора в таймере.

### Сценарий 2: Запуск и остановка таймера
1. Перейдите во вкладку **«Трекинг»**.
2. В блоке **«Быстрый запуск таймера»** выберите сотрудника, введите описание задачи и нажмите **«Запустить таймер»**.
3. Ниже появляется блок **«Активные таймеры прямо сейчас»** с живым отсчётом времени секунда в секунду.
4. Нажмите **«Остановить»** — таймер останавливается, а завершённая сессия сохраняется в истории.

### Сценарий 3: Повторный запуск таймера (защита от коллизий)
1. Запустите таймер для сотрудника А.
2. Попробуйте выбрать сотрудника А повторно: в селекте он будет помечен как недоступный, а под формой появится предупреждающий `Alert`.
3. При попытке программного вызова эндпоинта `/api/time-entries/start` сервер вернёт ошибку HTTP 400 с информативным описанием.

### Сценарий 4: Пустой отчёт
1. Перейдите во вкладку **«Отчёты»**.
2. В фильтре дат выберите диапазон, в котором заведомо нет записей (например, следующий год).
3. Интерфейс покажет аккуратный блок `EmptyState`: *«Пустой отчёт. За выбранный период времени нет данных об отработанных часах...»*.

### Сценарий 5: Сохранение данных после перезапуска
1. Запустите таймер или внесите запись.
2. Остановите dev-сервер (`Ctrl+C`) и перезапустите его (`npm run dev`).
3. Обновите страницу в браузере: все сотрудники, завершённые сессии и активные таймеры полностью сохранили своё состояние.

## 🏛️ Архитектурные правила и качество кода

- **FSD (Feature-Sliced Design)**: четкое разделение ответственности между слоями.
- **Strict React Style**: компоненты исключительно на стрелочных функциях, строго один `return` с JSX, кастомный компонент `<If>` вместо `&&` / `null`.
- **Лимит строк**: каждый файл приложения строго укладывается в 200 строк.
- **Чистота кода**: отсутствие неиспользуемых переменных, самодокументируемый код без лишнего шума.
- **БЭМ-нотация классов**: `block__element-subElement`.
